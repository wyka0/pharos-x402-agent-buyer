# x402 Agent Buyer — Pharos Atlantic Testnet

An autonomous, budget-gated, ROI-ranked, **idempotent** x402 buyer agent with four self-hosted paywalled endpoints, running on **Pharos Atlantic Testnet (`chainId 688689`)** with the official Atlantic USDC (`0xcfC8330f4BCAB529c625D12781b1C19466A9Fc8B`, EIP-3009).

Stack: **Next.js 15 (App Router) · TypeScript (strict) · Tailwind v4 · viem · wagmi v2 · Vitest** — plus `tsx` for the live verification script.

## 🧠 The four innovations

| # | Innovation | Where | What it buys you |
|---|------------|-------|------------------|
| 1 | **Cryptographic quote-to-settlement commitment** — `quoteCommitment = keccak256(scheme, network, resource, asset, payTo, maxAmountRequired, chainId, nonce)` issued inside every 402; `settlementCommitment = keccak256(quoteCommitment, txHash)` bound by the client and recomputed by the server from its **own** pricing | `src/lib/commitment.ts`, `src/lib/server/verifier.ts` | A malicious server cannot bait-and-switch price/recipient/resource mid-flight; a client cannot pay different parameters than challenged. Both sides verify the binding. |
| 2 | **Marginal utility / cost-per-signal ROI scorer** — every quote is scored `informationGain / priceUSDC`; plans reorder highest-ROI first; utility ground truth is the agent's **own** catalog, and a server's self-claimed utility is trusted at a 50% discount | `src/lib/roi.ts`, `src/lib/agent/tasks.ts` | The agent doesn't blindly buy anything under budget — it buys the **most informative** thing per USDC, and can't be talked into overpriced junk by a lying seller. |
| 3 | **Write-Ahead Payment Journal (WAL) with crash-recovery deduping** — `intentId → txHash` (plus the full signed payment payload) is persisted **before** every HTTP re-submit; a re-run recovers the paid proof and claims the data without paying twice. Additionally the EIP-3009 nonce is **derived deterministically from the intentId**, so even a crash in the broadcast→journal window cannot double-settle: the chain itself rejects the duplicate authorization | `src/lib/idempotency.ts`, `src/lib/agent/buyer.ts` | Agent crash mid-retry, dropped connections, 502/503s after payment — all recover safely. Proven by tests: a "second process" recovers both payments with `broadcasts.attempted = 0`. |
| 4 | **Atomic budget reservation locks** — in-flight `reservedSpend` is accounted synchronously (`reserve → commit / release`), and a promise-mutex serializes async reserve→commit sections | `src/lib/budget.ts` | Concurrent async tool calls cannot race past `totalBudget`; broadcast failures release their reservation cleanly. |

## Clearly Stated Limits & Architectural Boundaries

Read this before auditing. Everything below is a deliberate, documented boundary — not an oversight.

1. **Buyer key is server-side env.** The buyer signs with `TEST_USER_PRIVATE_KEY` from the git-ignored `.env.local`. It never reaches the browser bundle; the UI runs demos server-side and exposes only the address. For a browser-first deployment you would swap the `SignerLike` in `src/lib/agent/factory.ts` for a wallet connector signature — the rest of the pipeline is unchanged.
2. **Single-process server state.** The seller-side receipt store defaults to in-memory (`X402_RECEIPT_STORE=file` persists to `.data/receipts.json`). This is intentional for the self-hosted demo; multi-replica deployments need a real database (the store is a 4-method interface — swap it).
3. **WAL is single-writer.** `FileJournal` uses atomic tmp-file+rename, safe for one agent process (the documented deployment shape). Multi-writer journals need a DB with row-level locking. The write-ahead window between `PAYMENT_BROADCASTING` and the journaled `txHash` is covered by the deterministic-nonce property (chain rejects duplicate settlement), but a crash in that window leaves an *unresolved* intent that a human or a nonce-scan must resolve.
4. **No facilitator in the default path.** Settlement is self-broadcast by the buyer (EIP-3009 `transferWithAuthorization`, buyer pays gas — ~0.00008 PHRS per settlement on Atlantic). A `FacilitatorClient` adapter (`src/lib/settlement/broadcast.ts`) exists for external `/verify` + `/settle` services but is not wired by default.
5. **Plain-transfer fallback on testnet.** If the EIP-3009 path fails, the broadcaster falls back to a plain ERC-20 `transfer` of the exact amount (`allowTransferFallback`). Server-side verification is identical (on-chain `Transfer` log to `payTo` with the exact amount), but a plain transfer is not an EIP-3009 authorization — noted in evidence when it happens (it did not: live runs settled via EIP-3009, 83,300 gas).
6. **Synthetic data.** The four endpoints generate deterministic, nonce-seeded synthetic telemetry (audit findings, holder concentration, MEV scores). They demonstrate protocol mechanics, not real market data.
7. **Well-known dev keys in tests.** `tests/` and the simulated signer use public Hardhat/Anvil well-known keys (`0x59c6...690d`, `0xac09...ff80`) for signing only — they hold nothing and are not the env-configured buyer key. A `git grep` for the configured buyer key over tracked files returns **zero** hits (verify with: `git grep -l "$(grep TEST_USER_PRIVATE_KEY .env.local | cut -c24-31)"`).
8. **Trust-discounted advertised utility.** For endpoints outside the agent's catalog, `expectedUtility = 0.5 × advertisedUtility` (attacker economics). Catalog entries are the ground truth. This is a heuristic, not a oracle.
9. **Simulated demo mode.** The UI defaults to `mode: "simulated"` — identical protocol (real EIP-3009 signing, real header negotiation, real verifier logic) with settlements landing in a shared `SimulatedChain` instead of the RPC. Toggle to LIVE explicitly; live spends real testnet USDC.
10. **ROI planning is advisory for explicit manifests.** Demo B preserves its literal spec order (audit → MEV → whale); the ROI scorer annotates gates and drives auto-planned tasks (`buildSmartRoiTask`), it does not silently reorder user-specified steps.

## x402 protocol flow (as implemented, per docs.pharos.xyz/developer-guide/x402)

```
Agent                                Server (self-hosted endpoints)
  │  GET /api/x402/security-audit        │
  │ ────────────────────────────────────►│
  │  HTTP 402 + PAYMENT-REQUIRED (b64)   │  ← challenge: scheme=exact, network=eip155:688689,
  │ ◄────────────────────────────────────│    asset=USDC, payTo, maxAmountRequired,
  │                                      │    nonce, idempotencyKey, quoteCommitment
  │  decode → ROI gate → budget gate     │     (nothing signed yet)
  │  reserve budget → sign EIP-3009      │
  │  WAL pre-record → broadcast tx       │
  │  GET + PAYMENT-SIGNATURE (b64)       │
  │     + Idempotency-Key: intentId      │
  │ ────────────────────────────────────►│  recompute commitments → verify EIP-3009 sig →
  │                                      │  check on-chain receipt (USDC Transfer to payTo,
  │                                      │  exact amount) → idempotent receipt store
  │  HTTP 200 + PAYMENT-RESPONSE (b64)   │  ← settlement {txHash, block, amount}, receipt
  │ ◄────────────────────────────────────│    {intentId, replay}
  │  verify PAYMENT-RESPONSE vs proof    │
  │  ledger debit + DELIVERED_200        │
```

### Dashboard (dark-mode Agent Payment Plane)

- **One-click Demo A / Demo B / Smart-ROI plan** with live budget gauges, ledger table (PharosScan links), agent transcript, and the **402 negotiation inspector** showing verbatim Base64 headers decoded.
- **Idempotency retry simulator toggle** — injects the post-payment delivery drop that Demo A recovers from.
- **Settlement mode switch** — `SIMULATED` (zero-risk, full protocol) ↔ `LIVE` (real Atlantic USDC).
- **Dry 402 probe buttons** per endpoint — negotiate a challenge without paying.
